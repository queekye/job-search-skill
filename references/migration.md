# 换电脑继续求职

本页说明手工完整离线备份，包含本机公司资源。轮流跨电脑自动接续用[个人 WebDAV 同步](sync.md)；该入口只同步个人数据库和原件，公司资源通过[公共目录](public-resources.md)独立分发。

完整迁移保留所有本地账号的共享数据库、原件、偏好、任务、修改历史、导入身份，以及已接受和待审的公司资源。业务记录的 ID、修订、来源、用户决定、归档状态和官网核验时间不变；下述任务和机器设置重置使用新修订。受管附件按 `document_id` 及相对文件名恢复，无需沿用旧电脑的盘符或用户名。

这是一次交接。完成后从新电脑继续写入；两台电脑同时修改独立副本不会自动合并。旧电脑的自动跟进请由本人暂停后再迁移。

## 旧电脑

1. 在设置页确认**基础数据目录**，它包含共享 `career.db`；不能只备份 `accounts/<id>` 子目录。
2. 停止网页终端及使用该库的 MCP，等待公司资源操作结束。
3. 在运行包目录执行以下命令。自定义数据目录时加 `--data-dir '本机基础数据目录'`；否则使用与服务相同的 `JOB_SEARCH_DATA_DIR` 或用户目录 `.job-search-skill`。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 backup --output (Join-Path $env:LOCALAPPDATA 'CareerBackups\career-backup.zip')
```

命令使用 SQLite 完整快照，包含超过网页分页数量的记录及已归档数据，并核验附件与包内容。已存在的输出文件不会被覆盖。备份 ZIP 未加密，包含个人信息和简历原件；用自己的本地设备传输，勿存入公共目录、云同步盘或公开仓库。

当前支持数据库 schema 2；归档及展开内容上限 512 MiB，最多 20,000 个受管文件。未导入的外部材料和浏览器状态不在备份内，需另行保管。超限或损坏会拒绝恢复，不静默遗漏资料。

数据目录里自行保存的报告、截图、导出、研究笔记和历史验收文件也不自动进入此受管备份。需要这些证据时另做私有文件归档；源码 Git bundle、受管业务备份、补充证据分别携带。不要把整个个人目录作为公司资源包或公开项目归档。

## 新电脑

1. 准备 Codex、Python 和当前运行包，将 ZIP 解压到普通本地目录。**先恢复，再启动档案服务**。
2. 将私有备份复制到自己的本地目录，在运行包目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 restore --archive (Join-Path $env:LOCALAPPDATA 'CareerBackups\career-backup.zip')
```

默认恢复到新 Windows 用户的 `.job-search-skill`。也可加 `--data-dir '新本地目录'`，之后网页、MCP 的 `--data-dir` 或 `JOB_SEARCH_DATA_DIR` 均指向该目录。目标必须是新目录或空目录；已有档案不会被覆盖或合并。恢复失败时原档案和备份不变。

3. 运行 `Start.cmd`，选择原账号，核对偏好、推荐与申请、任务进度、材料和历史。需要原生工具时运行 `Install.cmd`，在新 Codex 任务中使用 `$career`。
4. 从任务页重新生成“交给 Codex”的说明，新说明引用新电脑目录和原任务 ID。执行前读取最新 `task.context`；有分页时继续读取。

运行中的任务恢复为 pending，保留原进度，并记录一次迁移状态变更；已取消或完成的任务保持原状态。历史中的旧路径不被全库替换。再次使用附件时先 `document.resolve({id})`，获取当前账号的新路径；历史外部文件路径需本人确认或重新导入，不凭旧路径继续上传。

## 新电脑需要重连的内容

- 招聘网站登录由本人完成；不搬运浏览器账号、cookie 或验证码。
- OTP 仅保留来源类型和地址供重配，Token 不进入备份；清除旧取码窗口和连接测试，新电脑保存并测试自己的来源。
- 每日跟进保留期望时间及时区，恢复后处于关闭状态，旧宿主任务 ID 清除。本人在新电脑重新生成并配置跟进任务，才登记新的实际启用状态。

恢复不改变官网流程，也不把原有 blocked、partial 或本人自报状态升级为已核验。数据库任务、岗位选择和敏感上传仍遵循当前账号与本次授权。

`profile.export` 的 JSON 只用于结构化记录互换，不包含完整续用状态；公开发行 ZIP 也不包含任何个人档案。完整迁移 ZIP 只在本机命令中处理，不增加网络同步、MCP 批量恢复或自动投递入口。
