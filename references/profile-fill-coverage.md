# 公司填表能力与接口

所有字段、条目身份、摘要、日期和附件路径在运行时从获准的私有档案传入。公开资源不绑定申请人的学校、学历、项目数量、暂停决定或现场个人记录。能力以当前公司版本的 `guide.md` 和 `manifest.json` 为准。

核心 `scripts/profile-fill.mjs` 提供 `fillResumeOnce({tab,plan,facts,authorization})`；`scripts/profile-upload.mjs` 提供 `uploadResumeOnce`。公司 `adapter.mjs` 导出其页面计划及条目 helper。这些入口填写/上传并读回，不保存或最终投递，返回 `saved:false,submitted:false`。

## 调用与条目匹配

1. 固定已接受版本，核对目标来源或租户、当前 route 和可见表单。读取该公司 guide 的参数及已观察选项；文档型包不执行字段说明。
2. 从本人事实建立必需教育、工作、项目或研究条目清单。用学校/标题、学历、职责和日期等组合身份匹配已有卡片；支持的卡片数量描述代码边界，不是网站名额或申请人应有的经历数。同学历多段经历仍需分别识别。
3. 全部提供值先与现值比较。补空或精确同值可继续，未知、重复身份、非空冲突或中途结构变化停止相关写入。索引只用于已经核验的当前卡片，不作为稳定身份。
4. 缺少卡片时仅调用该版本已观察的新增/复用入口，并取得对应授权；不支持时记录缺口，在任务获准范围发现新控件或交给用户补齐。ZTE 的项目和讯飞的实践具有有限新增能力，不能推导其他模块或公司的新增行为。
5. 逐项读回后，按 [材料完整性](workflow.md#材料完整性) 和 [保存核验](workflow.md#填写保存与异常恢复) 核对全部必需条目。保护性隐藏、遮罩值或字段完成标记不证明精确匹配或整份简历完整。

## 常用入口

- 京东：`profilePlan`、`resumeUploadPlan`、`fillParsedEducationOnce`、`fillExistingProjectsOnce`。
- 中兴：`profilePlan`、`updateSummaryOnce`、`ensureProjectOnce`。
- 讯飞：`profilePlan`、`resumeUploadPlan`、`fillParsedSectionsOnce`、`fillExistingResearchOnce`、`ensurePracticeOnce`。
- 蚂蚁：`profilePlan`、`resumeUploadPlan`、`correctProjectMonthsOnce`、`fillResearchOnce`。

实际参数和兼容别名只维护在公司 guide。学历、日期或选项未知时留空；年月不能擅自转换为具体日，网站解析结果需与本人事实核对。重复经历可按相同职责的官网模块承载，但摘要、论文和附件不能替代缺失的独立项目卡片。

附件共享按目标公司授权；解析可能覆盖已有表单，须独立 `replaceProfile` 授权。上传确认中断时读取状态或恢复现有确认，不重复上传。保存、刷新、最终投递与程序的字段动作分别记录。

## 验证与扩展

新增页面能力需要受限适配代码、字段说明、合成回归、独立版本与成员哈希。去除个人前提后的泛化以多学校、学历、可变卡片数、同类重复条目和冲突保护验证；仍不推断未观察的控件。

源码合成测试、源码现场调用、官网保存刷新、已安装版本调用分别记录。历史结构证据可帮助发现页面，新版本的泛化能力须重新验收，个人现场原件与结果留在私有目录。公开资源只描述可复用范围与尚未覆盖的路径。
