# 从事实构建关键词与筛选计划

首次发现岗位、用户新增公司/岗位或调整范围、以及本轮范围内公司已有流程全部结束后寻找其他岗位时读本文件。复核固定候选集时只更新受影响词族，无须重做全站搜索。先按 Skill 的触发规则分清活跃/已结束流程、候选与暂停公司。

## 1. 最小简报

将获准资料转成短表，保留来源定位。优先用用户当前确认的事实；旧附件中的说法与当前事实冲突时保留冲突。不要把 AI 草稿当作已确认经历。

| 内容 | 记录方式 | 用途 |
| --- | --- | --- |
| 招聘范围 | 用户原话、时间/版本；类型、公司、地区、行业、排除项 | 过滤与停止边界 |
| 发现触发 | 新公司/新岗位/补充或刷新/全部流程结束；记录范围、状态依据及未知 | 决定本轮检索公司；避开暂停、活跃流程和原已结束岗位 |
| 资格事实 | 学历、毕业时间、专业、工作许可等本次必需项；未知留空 | 对照当期官方条件 |
| 本人贡献 | 做过的动作、对象、方法、工具、交付物、规模/指标、角色；事实 ID | 职责匹配依据 |
| 硬约束 | 本人明确不能接受的地点、类型等 | 直接过滤 |
| 偏好 | 用户给出的层级、顺序与可妥协程度 | 检索范围与差异解释；同梯队仍并列 |
| 探索边界 | 愿意迁移到的职责/行业、可接受的证据缺口 | 扩展召回，不能声称胜任 |

偏好保留用户明确的层级和跨维度优先顺序；只给城市分层不等于同时给了城市、公司、职责之间的优先级。偏好用于检索与解释，不为同梯队制造精确顺序或名次。同 ID 的多城市先保留官方全集，与用户硬范围求 `allowed_cities` 交集；交集内的最佳已声明层级可以用于分析差异，但不表示用户已选城市或官网允许自行选择，选址机制未知单列。

压缩简报前做必要事实充分性检查：除了教育/经历条目，按目标职责与关键条件定向检索获准 CV 的专业技能、语言、工具、任务规模和成果区块。最小化是只保留相关事实，不能丢掉这些区块中已有的匹配或资格依据。抽出的事实保留原始 source、定位及确认 status；尚未确认的原文不升级为已确认能力。

条件暂时未知时，先在获准资料中定向查证，再仅对仍影响结论的缺口询问用户，例如必需毕业窗口。简报未收录或简历没写某技术不等于用户不会；也不能据相邻经历补出该技能。团队成果、项目总周期、论文主题不能自动变成本人的独立职责、参与日期或工程能力。

## 2. 每个词都要说明来自哪里

从事实中的“动词 + 工作对象 + 交付物”出发，再加入工具和领域。身份或学位只用于有证据的资格过滤，不能代替能力词族。

| 词类 | 含义 | 可支持的结论 |
| --- | --- | --- |
| `direct` 直接词 | 本人事实明确出现的任务/方法/工具 | 可以用于对应职责的匹配 |
| `alias` 同义词 | 语义相同的中英文、缩写、官网用语；指向同一事实 ID | 仅改变搜索表达，不扩大能力 |
| `explore` 探索词 | 业务邻近、可迁移方向或待验证技术 | 只扩大召回，匹配仍需回到本人事实 |
| `exclude` 排除词 | 用户明确排除的类型或已证实无关方向 | 标明范围；慎用全文排除以免误伤 |

合成示例：事实 F01 为“用 Python/SQL 清洗销售数据，建立周度指标报表并分析转化漏斗”。直接词可含数据清洗、SQL、指标分析、漏斗分析；同义词可含数据分析 / data analytics、BI / 商业智能（只在对应报表职责上使用）。“增长建模”“因果推断”“实时数仓”可以成为获准探索词，但没有对应事实时不能写成已有能力。行业词“零售”仅在事实或用户范围中有依据时加入。

为每个词族保留可执行条目：

```yaml
family_id: K01
objective: 召回以指标分析和报表为主要职责的岗位
fact_ids: [F01]
direct: [数据分析, SQL, 指标分析]
aliases: [data analytics, 商业分析]
explore: [增长分析]
exploration_reason: 与漏斗分析职责相邻，需完整 JD 验证
exclude: []
queries: [数据分析, 商业分析, SQL, 增长分析]
```

各族至少覆盖主要职责、核心工具/方法、用户明确的业务方向。不要机械扩成所有技术热词；一个新词必须说明它填补哪个召回缺口。工具词可用于发现标题泛化的岗位，例如“技术类”“解决方案”“业务分析”。最终判断回到 JD。

## 3. 搜索矩阵与官网初筛

建立 `公司/官方招聘入口 × 招聘类型/项目 × 词族 × 地区` 的任务表。只展开本次范围；城市或学位偏好不要复制成面向所有用户的规则。

对每个入口按以下次序执行：

1. 核对公司/租户、官方来源与当期招聘项目；记录本轮访问日期。列出同站与范围相关的项目/菜单，例如常规招聘与专项人才计划，分别确认所属类型；已有页面的项目或筛选值不能自动代表完整检索范围。官网规则未写当前年度或有效窗口时标明时效未知。
2. 先用官网明确支持的类型、项目、地区过滤器缩小范围。筛选器显示数量只是当前筛选结果数，不能当作剩余录用名额。
3. 依次搜索主要职责词、同义词、工具词，最后探索词。记录已观察到的搜索语义；未知语法时逐个单词/短词搜索，不假设网页支持 Boolean、多个词的 AND、`OR`、引号或全文检索。需要验证语义时用一个已知命中词和其组合做轻量对照，不把一次空结果当作无岗。公开搜索引擎可用 `site:官方域名 职责词` 找入口，收录时间和摘要不能证明岗位当前开放。
4. 将填入、输入读回、提交和结果读回分开调用，默认读回输入后再点击可见搜索按钮；不要在同一次调用中填入后立即 Enter 并假定提交了新值。记录实际输入、当前项目/筛选、提交时间，再检查主列表 ID/数量等结果状态稳定，并核对结果属于本次查询。`networkidle`、固定等待或输入框显示新词本身均不足以证明归属。无法从查询回显/结果语义确认时，用已知唯一岗位标题作轻量诊断，再恢复目标词并验证；诊断也计入记录。仍无法证明归属的结果仅作目录发现，`query_coverage_eligible=false`，不得计入该词族已完成统计。
5. 读取结果页并按实际分页方式遍历，登记页码/游标、筛选值、显示总数、主列表可见/唯一 ID 数、侧栏推荐数、新增与重复 ID、未读页。侧栏不能补入主结果计数。“没有更多了”只是界面提示；显示总数与实际累计主列表数量不一致，且无法由分页、虚拟滚动或去重解释时，保留 `coverage=partial` 与数量冲突。不要将首屏、末尾提示或预算停止当作穷尽。
6. 初筛只排除已证实违反当前硬范围的条目。标题不明显但领域/部门/摘要相关时进入 JD 待读队列；标题很像但无完整职责时同样不得提前推荐。
7. 命中太多时先用硬范围、职责词组合或明确的部门缩小；命中太少时逐步移除软筛选、换同义词或加入有理由的探索族。保留每次变更，不能悄悄扩大招聘类型或用户硬约束。

入口若重定向到招聘 AI 助手、简历匹配器或营销首页，先核对当前页面类型。助手回答、推荐解释和热招摘要不能代替官方岗位详情或资格条款。只沿可见的官方岗位链接、公开列表/返回入口继续；不为检索任务自动上传简历或个人事实。无法到达完整详情则记录重定向、已尝试入口与覆盖缺口，不补造 JD。

搜索记录最少包含：`query_id, company, official_entry, program, recruitment_type, filters, search_semantics, family_id, query, actual_input, submitted_at, observed_at, result_attribution, diagnostic_refs, query_coverage_eligible, result_boundary, pages_read, pages_unread, unique_job_ids, blocked_reason`。`result_attribution` 为 verified/unknown，并说明回显或诊断依据；`observed_at` 是稳定结果读回时间。`result_boundary` 分列当前项目/菜单、显示总数、主列表可见数/累计唯一数、侧栏数、末尾提示、数量冲突及 complete/partial/unknown。来源可用链接及必要短转述；不保存整站 DOM、账户信息或无关个人字段。

## 4. 覆盖、去重与停止

- **覆盖单位：** 记录哪些公司、项目、词族和页面已完成；“完整”只修饰这个边界。结果归属未证实的查询不计词族完成，数量冲突未解释的主列表保留 partial；目录发现可以保留候选 ID 及独立详情证据。公开搜索不支持枚举时标为开放集合，不提供未经证实的覆盖百分比。
- **召回去重：** 优先按公司/租户 + 招聘项目 + 官方职位 ID 合并多次搜索命中，保留全部来源。没有 ID 时用规范岗位 URL 和城市/项目/部门辅助关联；标题相同不自动合并，无法确定时保留待关联。
- **历史流程去重：** 以必要的已选/实际申请身份摘要排除原已结束岗位，保留其历史；发现同公司的其他官方 ID 可以继续精筛。同 ID 重开或换名称不自动成为新岗位，用户明确要求再考虑时另行记录。未选候选可复用并刷新分析，不自动成为申请，也不因旧候选存在就停止该公司的发现任务。
- **同岗多地：** 同一官方 ID 的多个城市可在一条中列出；城市、项目或 ID 独立的岗位仍保留独立子项。不要把公司聚合卡当作单个职位。
- **停止条件：** 已完成约定矩阵，且拟推荐条目完整 JD 已精筛；或达到事前声明的预算。用户未指定预算时按任务规模声明合理的本轮范围，再执行。连续两轮不同词族只得到重复/已排除项可停止扩词，但这仅表示当前策略收益很低，不证明官网已穷尽。
- **阻断条件：** 登录/验证码、速率限制、无法读取详情或缺少工具时停止该入口的重复尝试。继续其他可独立入口，报告已读与未读范围，不能通过登录或试投绕过阻断。

只在用户明确要持续寻找时安排下一轮；本 Skill 本身不创建监控或自动化。
