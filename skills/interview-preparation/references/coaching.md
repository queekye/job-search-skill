# 面试辅导流程

只读当前请求所需段落。共用账号、修订、权限与分页规则以 [career](../../career/SKILL.md) 和 [Agent 调用配方](../../../references/agent-recipes.md) 为准。

## 诊断和安排

先从岗位职责与主讲项目建立本轮目标，不把通用知识目录当成诊断结果。用户说“基础不牢”时，选能解释其项目关键决策的问题，让用户用概念、简单公式或例子作答；根据回答分辨概念混淆、计算缺口、实现不清、实验解释不足或表达失序。没有答复时可以先给最小准备框架，但不能记录具体误区或通过结果。

按照面试剩余时间及用户意愿安排重点。临近面试可优先主讲项目、相关基础和最可能造成误述的指标；更充分的时间可扩展系统知识和多轮模拟。建议时间预算与用户确认的安排分开，未知面试时间不补全。

## 项目和论文深挖

从已保存事实中选择本人决定主讲的项目或论文。用户没有指定时可以推荐候选并解释依据，保留“建议主讲”和“本人已选”的区别；读取材料不建立本人选择。

一张准备卡应能回答：

| 维度 | 证据与追问 |
| --- | --- |
| 问题 | 什么实际失败或需求触发了工作？问题在当时条件下为何值得解决？ |
| 本人贡献 | 团队做了什么，本人亲自设计、实现和验证了什么？未知角色不能写成主导。 |
| 技术选择 | 为什么用该方案？替代方法、约束和成本是什么？ |
| 实验依据 | 哪个对照或消融最能区分其他解释？评测、数据划分和泄漏风险如何处理？ |
| 结果口径 | 结果属于哪个方法版本、模型、数据、硬件和指标定义？哪些数字不能同时宣称？ |
| 局限 | 哪些条件失败？哪些是已有证据，哪些只是合理假设或下一步方案？ |
| 岗位联系 | 实际 JD 中哪项任务需要这些能力？缺 JD 时只说可能迁移，保留不确定性。 |

用“问题—本人决策—证据—结果与局限”组织讲述，避免以模块清单代替贡献。不为了显得新颖而否认旧工作的历史背景；谈现代模型能否替代时，区分当年的贡献、今天仍待检验的问题和未执行的新基线。项目间的研究主线属于叙事建议，不能反向建立事实库关联。

准备卡 `record_id` 指向原始事实；`source_versions` 固定实际读取的修订。`narrative/contribution/evidence/limitations` 中明确“已记录事实”“建议表达”“待核验/拟开展”。来源链接、观察时间、实验配置可写在 `evidence` 中，不能混入事实正文。没有证据时明确缺项，不凭同类论文常见做法补细节。

## 知识练习

每次短循环：

1. 提出和本轮目标有关的题目，说明必要条件和回答长度；题目是通用演练就如此标明。
2. 用户回答后，先概括已答对的机制，再指出能定位的误区、遗漏和影响。区分口误、表达不清和概念错误。
3. 用最少必要原理、公式或例子修正。对技术上不确定或近期变化的内容，先核验原始论文或官方文档，注明版本和日期；不把宣传语当作证据。
4. 改变一个条件复测，例如序列长短、输出长度、批量、训练目标或实验约束；不要仅要求复述刚给的答案。
5. 依据本次答复保存状态：`unassessed` 没有可评估回答；`needs_review` 已见具体误区或关键缺漏；`passed` 已在当前题目范围正确解释并通过必要追问。`retested_at` 只在实际复测时写含时区时间，否则为 null。

反问追求决策依据和证据，避免连续抛出大量题目而不反馈。用户明确要求直接讲解时先讲解，不强迫考试；讲解后的状态仍待评估。稳定基础与“最近发布了什么”分开，当前新模型细节不足时缩小结论范围。

## 模拟和复盘

按实际可用时间模拟开场、主项目、基础延伸、局限和反问；题量按用户状态调整。未知面试形式不编造算法题或轮次安排。公司题源未核实时称通用模拟，不称内部题或该公司必考。

遇到尖锐追问，让用户承认真实边界，并说明已知原理、亲自做过的证据和下一步如何验证。不要编造“做过”来补弱点，也不要建议隐藏已知限定条件。结束后优先记录会影响表现的少数误区、修正表达和下一次复测题，而不是泛泛评价自信或基础好。

## 保存与接续

读 `career_get(operation="interview.schema")` 获取当前版本；维护的文件为 [schemas/interview-task.json](../../../schemas/interview-task.json)。所有内容保存在原数据库的 `custom` 任务中，不新增平行档案或私有源文件。

| task.data 字段 | 含义 |
| --- | --- |
| `workflow/schema_version` | 固定 `interview_preparation` / `1`，供网页和工具识别 |
| `application_id` | 本地申请记录 ID，可 null；不是官网申请编号 |
| `scheduled_at/round` | 用户或可靠来源给出的时间与轮次；未知为 null，完整时间含时区 |
| `selected_record_ids` | 当前准备使用的项目、研究、论文等事实 ID；本人未选时不冒充已选 |
| `source_versions` | `{事实ID:实际读取的revision}`，用于接续时发现来源变化 |
| `plan` | `{topic,priority,status}`；优先级 high/medium/low，状态 pending/in_progress/completed |
| `project_cards` | `{record_id,narrative,contribution,evidence,limitations,questions:[]}`；讲述建议与事实标明边界 |
| `practice` | `{question,answer_summary,feedback,misconceptions:[],status,retested_at}`；只记录实际回答摘要，不伪造回答 |
| `summary` | 本轮完成范围、关键缺口、待核验问题与下一步；建议和来源冲突明确标注 |

`task.save` 更新携带新读取的 `id/revision`；提供的 `data` 会替换原任务数据，应先合并保留已有与未知字段，再提交。面试任务的 `task.context.interview_context` 提供 `application/selected_records/current_versions/issues/references_complete`，仅解析本任务引用的本账号申请及项目、研究和论文，不替代完整的来源审阅。`source_changed/source_version_missing/reference_unavailable` 表示需要复核；不能把 current_versions 直接复制到 pins 表示已审阅。准备卡源修订变化时先比较差异并复核相关讲述与结果，不因为原卡曾完成就沿用旧数值。应用或资料缺失时可以保存无关联的准备任务，不能为了通过关联检查新建虚假申请。

题目和摘要适度压缩，遵循任务数据大小限制；不要复制整份简历、附件原文、无关申请历史或凭据。增量写入后读回关键字段以核对持久化；冲突重新读取。暂停/取消、同步只读和原任务状态分别尊重，不将旧任务文字当作本轮外部授权。
