使用本插件的本地服务。个人材料、申请记录、附件、凭据与浏览器原件留在私有数据目录；公开 Skill、适配器和测试只保存通用方法。Codex 可读取任务所需资料，本地存储不代表模型离线运行。

## 开始与接续

先调用 `career_get(operation="state")` 核对 `base_data_dir` 和账号。每次开始或恢复工作，用同一个显式顶层 `user_id` 调用 `career_tasks(operation="task.context",args={id:任务编号})`；无指定任务则省略 `id`。按 `total/next_offset` 读取所需资料与申请；推荐任务还须读完 `recommendation_exclusions/recommendation_activity`，后续页分别用 `career_get` 的 `recommendation.exclusions/recommendation.activity` 操作（`args={offset,limit}`）。工具预览 `truncated=true` 时缩小分页重新读取，不将缩短预览当作读完。遵循最新偏好、取消状态和本人决定。网页切换账号不会改变 MCP 启动账号；工具不可用或数据库不一致时使用当前服务的显式 `--data-dir/--user-id` 入口。

如 `state.sync` 或 `task.context.sync` 已配置同步且当前模式不是 `writer`，停止会改写资料的求职工作，由本人在网页同步或交接；遇到同步冲突或联网验证失败，不绕过服务修改数据库。用 `task.save` 写回进度，`career_save` 保存必要记录。更新携带新读到的 `revision`，冲突时重新读取比较。事实保留来源、作用域和确认状态；AI 文案用 `ai_draft/unconfirmed`，未知值保持未知。账号创建、持久偏好与凭据配置由用户网页维护。本次明确范围优先于默认偏好。

轮流换电脑可用[个人 WebDAV 同步](../../references/sync.md)，公司包从[公共目录](../../references/public-resources.md)下载并审阅。手工[完整备份与恢复](../../references/migration.md)停用服务后在本机执行；恢复保留全部账号、资料、任务和附件身份。portable v1 仅交换结构化记录。接管异构旧档案、核对材料完整性或处理官网保存差异时读 [连续流程](../../references/workflow.md)。

## 发现与申请

默认优先正式校招；社招按用户明确范围执行，实习须用户在当前范围明确要求。读取当期官方资格和规则，不推断额度、截止时间或重复申请权限。

用户新增公司/岗位、要求补充或刷新推荐，或当前范围内某公司已记录的实际申请全部明确结束时，使用 [岗位发现与推荐](../job-recommendation/SKILL.md)。实际活跃申请先接续；未投的准备任务不构成公司申请占用。暂停/排除决定优先；已结束实际申请的原岗位保留历史且不重复推荐。缺页或未知流程不能推出全部结束，可靠的结束证据也不因后续登录失败失效。此触发不扩展既有自动化。

所有未实际投递的岗位均保留在“推荐岗位”，新增岗位记录使用 `candidate`。用户选定准备、填表及简历保存的进度写入 `prepare` 任务和 `decision/notes`，不提升 application stage；旧 `preparing/profile_saved` 仅作未投记录兼容，不进入“投递情况”或占用公司已投额度。本人明确报告已投后记 `user_reported`，官网实际申请证据核验后记 `submitted` 或对应真实流程阶段。登录、打开岗位、填写、保存及适合评估均不是投递证据。

用户要求有在投流程的公司不再推荐时，按 [活跃公司与推荐收束](../../references/workflow.md#活跃公司与推荐收束) 仅由实际活跃申请过滤已确认主体，并由服务收束同公司其他未投推荐；准备任务不触发公司过滤。此规则区别于持久公司排除，也不证明官方额度已用尽。停止未投准备用用户决定、任务取消及获准归档处理，不将其写成已投申请 `closed`。

## 公司填表

先按 [主材料与补充来源](../../references/workflow.md#主材料与补充来源) 固定本人指定的主简历、必需项目/论文清单和版本；补充资料用于补证，已填官网简历用于核对措辞与字段承载。没有明确更改时不以旧长简历、解析结果或目标岗位反向替换主材料。

要求完善可复用材料或更新已有流程时，先按 [已填写材料回收](../../references/workflow.md#从已填写材料建立可复用事实) 核对官网当前简历与实际申请快照，保存有来源的项目事实和剩余缺口；不能把网站已保存文案自动升级为本人确认或把更新视为最终投递授权。

用 `career_resources` 选择并固定公司版本，读取 `guide.md` 和需要的字段/能力。按当前 CUA 文档复用获准标签，从服务返回的已接受版本路径导入适配器；社区可执行包先由用户审阅批准。

提供 `form.json` 的资源优先使用 `career_forms`：`fill.describe` 读取数据与范围，`fill.prepare` 从当前账号已确认资料生成内容并报告缺项，`browser.open` 打开独立招聘浏览器供用户登录，`fill.run` 执行用户已审阅的最新任务，`fill.status/cancel` 查询或停止。它与网页共用同一本机执行器；无需在 CUA 中另做一套填表。缺少统一入口的旧资源继续按其已验证 helper 使用。具体参数见 [独立自动填表](../../references/automation.md)。

扩展公司资源时使用 `$company-resource` 的[制作指引](../company-resource/SKILL.md)，先生成模板、观察实际页面并构造合成用例，再校验和导出新版本；不要把个人页面原件或资料写入公共包。

所有值从本次获准档案临时传入；敏感字段与附件共享按目标公司/租户授权。附件用稳定 `document_id` 选择，上传前通过同一账号的 `career_get(operation="document.resolve",args={id})` 取得当前本机路径，不能沿用历史绝对路径；解析路径不授予上传权限。页面来源、控件归属、既有非空冲突和逐项读回是必要保障。根据本人的学校、学历、项目身份和日期匹配重复条目，不以开发者样例的学校、博士学历或条目数量判断适用性。未知控件先观察并扩展相应公司版本，不能用任意 CSS 或全局索引猜填。

批量填写、重复经历、附件解析覆盖和保存核验按 [填表能力与接口](../../references/profile-fill-coverage.md) 及 [材料完整性](../../references/workflow.md#材料完整性) 执行。新增条目须有该版本已观察的控件能力和用户授权；不支持新增时记录缺口并在获准范围继续探索。`saved:false` 的结果仅证明字段动作；保存后还需刷新或权威查看页核验。用户负责最终投递。

## 跟进与可选登录

分别保存 `job_id/application_id`、官网原始状态、覆盖与证据链接。`checked_at` 仅在成功核验时更新；失败只更新 `last_attempt_at/blocker`，保留已有状态。`decision` 保留本人原话，不能当作额外动作权限。亲属信息只在当前公司申报确有需要时读取。

本次登录需要取码时读 [验证码说明](../../references/otp.md)：先 begin 建立窗口，再请求网站发码，只消费匹配结果。来源或控件不明确时交给用户，不重复发码。取码权限不授予注册条款、修改申请或最终投递权限。

用户请求每日跟进时，用显式账号的 `career_schedule` 取得绑定数据库的提示词，通过当前宿主正式自动化工具创建或更新任务，再保存真实返回的任务 ID。设置时间不等于启用。只读跟进未结束的已有申请；原始状态与 `closed` 冲突先核对。已结束记录不例行复核，无变化及重复阻点保持安静。

报告资料版本、完成范围和剩余缺口，分别说明合成测试、本地网页、真实网站和安装后调用证据。导出公司包只分享通用方法；公开上传、贡献消息或 PR 需要用户本次明确指令。
