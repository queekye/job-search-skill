# WebDAV 跨电脑接续

适用于主要轮流使用、一次一台电脑写入。网页和 MCP 仍读写各自本机 SQLite；程序通过 WebDAV 交换一致的个人快照，不直接把活动数据库放进网盘或网络文件系统。

## 配置与交接

1. 两台电脑安装同版本或兼容版本。在网页“设置 → 跨电脑同步”填写自己的 HTTPS WebDAV **已有基础目录**、用户名、应用密码和工作区目录名；基础目录必须已存在。两台电脑的基础地址和工作区一致。
2. 在有资料的第一台电脑保存并完成首次同步。第二台使用新的空个人数据目录，配置后读取远端资料。若本机已有独立资料，停止覆盖并保留它；先完整备份，再用新空目录接入，首版不合并两份资料。
3. 换机前在当前写入电脑执行“同步并交接”，确认成功。新电脑同步后，若仍显示只读，点击“在此电脑接管”。旧电脑不再写入；已经只读的电脑不会自动抢回写入权。
4. 旧电脑损坏或无法打开时，可以在新电脑明确接管。先关闭另一台电脑的服务与求职任务；旧电脑尚未上传的改动不会被合并，重连时保留本机分支并报告冲突。

保存设置不等于成功同步。离机前确认页面没有错误、存在成功同步时间且没有未同步改动，执行“同步并交接”后应显示只读。新电脑只需公开项目和相同 WebDAV 设置即可拉取受管求职数据，无需复制整个旧机目录。网页显示错误时先检查最终 WebDAV 地址、应用密码及服务能力；[完整离线备份](migration.md)作为备用，不能以保存配置代替上传成功。

启用自动同步后，网页服务或 MCP 运行期间约每 30 秒检查一次。关闭程序后不在后台运行。首版启用 WebDAV 后，修改业务数据需要联网验证当前写入权；断网时可读取已有资料，修改会被阻止。关闭“自动同步”只停止周期检查，仍可立即同步，且写入权规则仍生效。网页“停用同步”恢复本机模式并保留资料及加密配置；其后改动不上传，重新保存启用时检查冲突。换机应先交接，不能把停用当作成功上传。

## 同步范围

| 内容 | 位置与处理 |
| --- | --- |
| 全部账号、档案、申请、偏好、任务、修改历史、导入身份 | 数据库，一起同步，保留 ID、来源、未知事实与官网核验时间 |
| 简历等已导入原始附件（包括归档附件） | 数据库外的 `documents/`，与快照一起同步，按 `document_id` 解析当前路径 |
| 公司资源、版本锁、接受记录、待审包 | 公共资源，不参与个人同步；各机从[公共目录](public-resources.md)下载或离线导入 |
| WebDAV 与验证码密码、验证码窗口、浏览器登录 | 留在本机；WebDAV 密码通过 Windows DPAPI 保存，不返回网页或 MCP |
| 自动化的启用状态、宿主任务 ID、允许重新登录 | 留在本机；期望时间、时区及本人偏好同步 |
| 自行另存的报告、截图、导出、研究笔记及未导入材料 | 不属于受管同步；另行私有传输或先导入支持的原件 |

一个工作区共享数据库的**全部账号**，不是远程多人账户或单账号分享。新电脑需重新登录招聘网站、配置本机验证码来源及宿主自动化；当前写入权未持有时停止会写入资料的求职工作。新电脑获得写入权时，旧电脑运行中的数据库任务转为待继续，新增任务历史，不更改官网状态或完成/取消的任务。

仅备份 `career.db` 可保留结构化数据和附件提取文本，不能恢复原始附件。数据库开启 WAL，直接复制活动 `.db` 还可能漏掉已经提交的事务；本项目使用 SQLite backup API 生成快照。[SQLite 说明](https://sqlite.org/wal.html)、[备份 API](https://sqlite.org/backup.html)。手工完整离线迁移仍按[备份与恢复](migration.md)执行，包含本机已接受公司资源；它与个人自动同步是两个入口。

## 故障与存储

服务先上传 UUID 命名的不可变 ZIP，再用文件版本标识 / `If-Match` 更新 `latest.json`。首次接入用独立测试对象验证错误版本拒写、正确版本更新和旧版本拒写。标准带引号 ETag 与坚果云裸版本 token 均可使用，保留服务返回形式；弱标识和未执行条件更新的服务会被拒绝。

首次创建优先使用 `If-None-Match:*`；忽略此条件的服务改用临时头文件 `MOVE` 到 `latest.json`，带 `Overwrite:F`。探测验证已有目标不会被覆盖、空目标可创建，才启用该方式。坚果云的裸 ETag 和 MOVE 方式已按其实际响应适配；不会删去版本检查或退回最后写入覆盖。旧版本能力缓存升级后重新探测。[HTTP 条件更新](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)、[WebDAV MOVE](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.9)。

并发改动、未知工作区或损坏快照都停止覆盖，本机资料保留。发生冲突先做完整本机备份，核对两份差异后通过正常记录编辑处理，不删除数据库来“修复”。

接收快照先核对大小、路径、哈希和数据库，再持有本机跨进程门禁交接目录。数据目录旁保留一份最近接收前的 `.career-before-sync-*` 本机恢复目录，以及用于中断恢复的小型记录；这些目录同样含私有资料，不发布或提交 Git。所有网页和 MCP 进程须使用本版本，不能让旧版本或外部脚本绕过门禁写入数据库。

远端通常保留最近 5 个个人快照；删除失败或发布中断可能留下额外文件，不影响最新快照，可由存储管理员清理。快照是**未加密的私有 ZIP**，HTTPS 只保护传输；存储服务管理员可以读取内容。使用本人控制的私有目录，不能放 GitHub Pages、Cloudflare Pages 或公开桶。首版没有端到端加密或多写者离线合并。

## 其他方案

WebDAV 快照适合本项目的轮流换机方式。Syncthing 或网盘可传输已关闭、完整生成的备份，但文件同步不能合并数据库事务。若以后需要两台电脑同时在线编辑，优先增加经过身份认证的中心业务 API，由一份数据库处理并发；本机回环服务不能直接改绑公网地址。只有明确需要多设备同时离线修改时，才考虑记录级增量同步、删除标记和冲突解决，这会显著增加维护代码。
