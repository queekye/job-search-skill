使用本插件的本地服务。个人材料、申请记录、附件、凭据与浏览器原件留在私有数据目录；公开 Skill、适配器和测试只保存通用方法。Codex 可读取任务所需资料，本地存储不代表模型离线运行。

## 开始与接续

先调用 `career_get(operation="state")` 核对 `base_data_dir` 和账号。每次开始或恢复工作，用同一个显式顶层 `user_id` 调用 `career_tasks(operation="task.context",args={id:任务编号})`；无指定任务则省略 `id`。按 `total/next_offset` 读取所需资料与申请，遵循最新偏好、取消状态和本人决定。网页切换账号不会改变 MCP 启动账号；工具不可用或数据库不一致时使用当前服务的显式 `--data-dir/--user-id` 入口。

如 `state.sync` 或 `task.context.sync` 已配置同步且当前模式不是 `writer`，停止会改写资料的求职工作，由本人在网页同步或交接；遇到同步冲突或联网验证失败，不绕过服务修改数据库。用 `task.save` 写回进度，`career_save` 保存必要记录。更新携带新读到的 `revision`，冲突时重新读取比较。事实保留来源、作用域和确认状态；AI 文案用 `ai_draft/unconfirmed`，未知值保持未知。账号创建、持久偏好与凭据配置由用户网页维护。本次明确范围优先于默认偏好。

轮流换电脑可用[个人 WebDAV 同步](../../references/sync.md)，公司包从[公共目录](../../references/public-resources.md)下载并审阅。手工[完整备份与恢复](../../references/migration.md)停用服务后在本机执行；恢复保留全部账号、资料、任务和附件身份。portable v1 仅交换结构化记录。接管异构旧档案、核对材料完整性或处理官网保存差异时读 [连续流程](../../references/workflow.md)。

## 发现与申请

默认优先正式校招；社招按用户明确范围执行，实习须用户在当前范围明确要求。读取当期官方资格和规则，不推断额度、截止时间或重复申请权限。

用户新增公司/岗位、要求补充或刷新推荐，或当前范围内某公司已记录的已选准备/实际申请全部明确结束时，使用 [岗位发现与推荐](../job-recommendation/SKILL.md)。活跃流程先接续；暂停/排除决定优先；已结束原岗位保留历史且不重复推荐。缺页或未知流程不能推出全部结束，可靠的结束证据也不因后续登录失败失效。此触发不扩展既有自动化。

未选候选用 `candidate`，在“推荐岗位”展示资格、匹配、差距和未知。用户选定具体岗位后进入 `preparing`；本人报告已投记 `user_reported`，官网确认后记 `submitted`。登录、准备通用简历、填写或保存均不表示选岗或投递。

## 公司填表

用 `career_resources` 选择并固定公司版本，读取 `guide.md` 和需要的字段/能力。按当前 CUA 文档复用获准标签，从服务返回的已接受版本路径导入适配器；社区可执行包先由用户审阅批准。

所有值从本次获准档案临时传入；敏感字段与附件共享按目标公司/租户授权。附件用稳定 `document_id` 选择，上传前通过同一账号的 `career_get(operation="document.resolve",args={id})` 取得当前本机路径，不能沿用历史绝对路径；解析路径不授予上传权限。页面来源、控件归属、既有非空冲突和逐项读回是必要保障。根据本人的学校、学历、项目身份和日期匹配重复条目，不以开发者样例的学校、博士学历或条目数量判断适用性。未知控件先观察并扩展相应公司版本，不能用任意 CSS 或全局索引猜填。

批量填写、重复经历、附件解析覆盖和保存核验按 [填表能力与接口](../../references/profile-fill-coverage.md) 及 [材料完整性](../../references/workflow.md#材料完整性) 执行。新增条目须有该版本已观察的控件能力和用户授权；不支持新增时记录缺口并在获准范围继续探索。`saved:false` 的结果仅证明字段动作；保存后还需刷新或权威查看页核验。用户负责最终投递。

## 跟进与可选登录

分别保存 `job_id/application_id`、官网原始状态、覆盖与证据链接。`checked_at` 仅在成功核验时更新；失败只更新 `last_attempt_at/blocker`，保留已有状态。`decision` 保留本人原话，不能当作额外动作权限。亲属信息只在当前公司申报确有需要时读取。

本次登录需要取码时读 [验证码说明](../../references/otp.md)：先 begin 建立窗口，再请求网站发码，只消费匹配结果。来源或控件不明确时交给用户，不重复发码。取码权限不授予注册条款、修改申请或最终投递权限。

用户请求每日跟进时，用显式账号的 `career_schedule` 取得绑定数据库的提示词，通过当前宿主正式自动化工具创建或更新任务，再保存真实返回的任务 ID。设置时间不等于启用。只读跟进未结束的已有申请；原始状态与 `closed` 冲突先核对。已结束记录不例行复核，无变化及重复阻点保持安静。

报告资料版本、完成范围和剩余缺口，分别说明合成测试、本地网页、真实网站和安装后调用证据。导出公司包只分享通用方法；公开上传、贡献消息或 PR 需要用户本次明确指令。
