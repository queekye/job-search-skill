# 个人资料与人工 / Agent 共用能力设计

日期：2026-10-13。状态：整体目标设计及 core 0.4.0 实现进度。教育、项目、论文已有类型化字段、专属编辑器、显式关联、独立来源及事务迁移；本轮实现唯一意向、旧行整理、简历方案组合与 Markdown 导出、公司答案及本人公司决定。完整公司映射、通用合并和新增细分字段仍为后续目标。字段清单见 [profile-fields-v2.md](profile-fields-v2.md)，实际接口见 [开发契约](development-contract.md)。

## 产品定位与问题

产品首先是人能独立使用的本地求职工具：编辑资料、维护材料、筛选岗位、记录投递与进度。MCP 提供同一业务能力的另一种访问方式；Skill 教 Agent 使用工具。网页、MCP、独立填表运行器共享领域服务、校验、修订、历史和 SQLite 数据库。

保留现有账号隔离、revision、history、document_id、任务上下文、单写者同步和版本化公司包，无需重建平台。本轮处理的原有问题是模型与展示：

- 教育导师、实验室、排名和学习形式塞在 description，不能直接编辑或确定性取值。
- experience 混合项目、工作、研究、论文、技能、奖项；同一研究在不同模块重复出现。关联实体与真正重复行没有区分。
- preference 的 category/value/notes 同时保存事实、方向、JSON、公司答案、临时授权和旧指令；settings.preferences 又是独立入口，产生两个有效偏好来源。
- 公司字段别名与主档案不一致：mobile/phone、academy/department、tutor/supervisor、researchField/researchDirection。
- task.context 没有解析后的有效意向、适用范围和冲突状态，迫使 Agent 每次自行解释旧文本。

## 统一边界

| 部分 | 数据 | 网页入口 | 当前业务入口 |
| --- | --- | --- | --- |
| 个人事实 | 基础、教育、工作、项目、研究、论文、技能、语言、证书、奖项、家庭申报 | 个人资料分区表单 | profile.schema/get/patch |
| 求职意向 | 招聘类型、城市梯队、主线与探索方向、排除职责、行业、薪资、到岗时间 | 独立的一份意向表单 | intention.get/patch |
| 简历方案 / 公司答案 | 选用经历、文案版本、特定问题答案 | 简历方案 / 公司答案审阅 | resume.list/get/save/compose、answer.list/get/save |
| 求职流程 | 推荐、选岗、实际申请、进度、公司决定、任务 | 岗位、投递、任务、公司决定 | application/recommendation/task、decision.list/get/save/archive |

招聘信息来源归公司问题；开发语言归技能；个人简介归基础或文案版本；毕业日期归教育；暂停公司归流程决定。它们不继续伪装成偏好行。

任务约束绑定 task_id、范围与有效期；历史单次授权不自动成为全局许可。本人长期确认的意向长期保留；当前任务覆盖范围在上下文明确显示，不能默默改写长期配置。

## 公司要求依据

本轮基于仓库现有 fields.json、guide 和已观察 helper，不声称实时观察了所有公司全部必填项。只读 / 文档包不能计为完整填表支持。

| 来源 | 已观察要求 / 差异 | 核心归属 |
| --- | --- | --- |
| 字节 | 基础、教育、经历专业文本 | 基础 / 教育 / 项目或工作 |
| 京东 | 导师、实验室、研究方向、专业类别、学历、学习形式、最高学历、双学位、排名；项目日期 / 角色 / 描述 | 教育扩展、项目；来源选项为公司答案 |
| 中兴 | 项目描述与职责分开、参与年月、简介 | 项目背景 / 职责 / 成果，简历方案 |
| 讯飞 | 教育专业字段、地区、开发语言、实践、论文、附件 | 教育、技能 / 语言、项目或工作映射实践、论文 |
| 蚂蚁 | 教育专业字段、研究、论文状态、项目、附件 | 教育、研究 / 论文、项目；otherInfo 为公司答案 |
| 腾讯 | 教育研究方向和论文、项目名称 / 角色 / 描述、补充说明 | 关联教育 / 研究 / 论文、项目、公司答案 |
| 阶跃星辰 | 部分所在地 / 证件字段 | 基础 |
| 其他包 | 申请读取或入口说明 | 保留范围，后续逐家补证据 |

规范字段用 snake_case，站点 camelCase 和枚举由公司映射转换。基础 mobile → phone，教育 academy → department，tutor → supervisor_name，researchField → research_directions。日期精度、数组拼接和站点枚举映射须明确，不能按名称猜值。

公司包将来分开声明规范来源字段、网站标签、条件必填、枚举、长度、可读 / 可填 / 可验证范围和证据日期。条件依学历、招聘项目、页面变化，不设全公司静态必填表。个人特殊答案留私库；旧版本不改字节，变更映射要升级版本和哈希。

## 网页设计

个人资料分基础、教育、工作 / 实习、项目、研究与论文、技能 / 语言 / 证书、奖项、按需家庭申报。项目分别编辑背景、职责、成果和技术。论文编辑书目信息并引用关联项目；引用不复制可编辑事实。

求职意向独立为一份表单。设置只放同步、资源、验证码、宿主跟进。公司例外在填写审阅页和集中列表展示；旧导入行在历史 / 待整理查看。缺项按目标公司 / 岗位计算，不能用全局百分比证明任一网站完整。

编辑支持未知值、字段来源、最近修改、撤销、冲突比较、导入对照。原文和 Agent 推断不混为已确认事实。“Agent 任务”改为“任务”，人可以直接创建待办和手工完成，AI 是可选执行方式。人工资料维护、申请记录和简历材料管理无需模型。

## 已实现服务 / MCP 契约

- profile.schema 为 UI、校验、MCP 的共同字段来源；避免三套手写定义。
- profile.get 分页返回实体、字段证据及修订，关系通过 profile.relation.list 独立分页。profile.patch 精确改字段；缺省不变，null 未知，clear 显式清空，空列表为确认无条目。
- intention.schema/get/patch 使用唯一 settings.preferences 与 settings revision。高级意向字段保持类型，cities 为 allowed_cities 兼容别名；修改仅限本人网页，MCP 只读。
- legacy.preview/apply 分类旧行、补确定的缺失值及归档明确重复/开发说明，提交核对全量 digest 并保存幂等收据。无法确定的值继续待审，历史指令不成为当前授权。
- resume.list/get/save/archive 管理事实 ID、顺序、文案及原件引用；resume.compose 解析方案与目标公司，确定性返回正文、独立审阅信息与 pins，不按关联自动追加条目。AI 改写为待审草稿，原事实不变。
- answer.list/get/save/archive 精确管理公司/问题/招聘范围答案；不确认、过期、冲突或引用事实变化时提示复核且不可用。decision 的暂停/排除/恢复由本人维护，Agent 读取执行边界。
- source_versions 锁定编辑时读取的事实修订，源指纹标记独立文案和答案需复核；重新确认仅限本人，普通改写不能消除已有复核状态。
- profile.migration.preview/apply 提供差异、冲突、全量版本锁和幂等收据，原记录保留在修改历史。

`profile.merge.preview/commit`、教育与研究关系、细分实体以及完整方案到公司字段映射仍待实现。当前 `company_form` 仅检查已接受包声明字段及原事实，`scope_complete=false`；方案预览不代替真实网站填表和保存验收。

HTTP / MCP 只负责传输、actor 与账号绑定，调用相同领域服务。AI 不直接写 SQL；Skill 不存个人事实或取代服务校验。凭据、敏感共享、公司包启用和最终投递各自遵守现有权限。

## 数据库建议

继续 SQLite。当前 `records` 保存固定 schema 的类型化 JSON 与稳定 ID，`profile_relations` 关联项目、研究、论文，`profile_sources` 保存字段来源和确认。按查询需求索引，无需为了表单把每个字段建成单独表。

当前每账号一行 `settings.preferences` 保存意向；`records` 内 `resume_variant` 存选用 ID 与文案、`company_answer` 按公司 / 网站 / 问题 / 招聘范围保存答案与事实引用、`company_decision` 保存暂停 / 排除 / 关注。记录审计保留 before/after 与 actor，迁移保留事务收据。独立 task_constraints、授权引用和公司决定期限属于后续目标，不能视为已有授权引擎。

可先在现有表落实类型化数据与唯一入口，是否拆表由查询和迁移成本决定。但旧资料和偏好行最终是只读历史，不能长期双写。SQLite user_version、字段 schema、portable、公司包契约与 MCP 协议分别版本化。

## 迁移闭环

1. 完整私有备份；预览每条旧记录目标、证据、关联、冲突和未解析内容。未知内容保留原文并进待整理区。
2. 预计毕业、实际毕业、拿证日期分开；不把公司预计值变成全局事实。“其他”排名是表单答案，不能伪装百分比。论文年不能代替项目参与起止。
3. 在事务中检查账号和全部 revision；建立旧 ID 映射、幂等迁移和审计。保留 imports 身份以防再次导入制造重复。
4. 论文与项目保持独立；确证同一事实的研究内容关联或合并。冲突按本人证据决定，不用 updated_at 自动选值。
5. 更新 backup/restore/logical_digest/WebDAV/portable/task.context/forms pins 的表与文件白名单、版本检测。新业务表必须进入完整快照和摘要；旧电脑拒绝不兼容接管，不能静默丢新字段。
6. 旧填表计划变成需重新准备，保留本人答案。实体 / 关系 / 意向 / 公司答案变更使 pins 失效；不修改官网状态和核验时间。
7. 回滚前备份迁移后的改动；不能直接把最新库覆盖为旧快照。

## 后续顺序与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | 字段 schema、别名映射、关系、旧记录分类与迁移预览 | 不丢事实 / 来源 / 范围；幂等；冲突值不自动覆盖 |
| P1 | 共用 get/patch、唯一意向、网页分区、MCP 同等接口、字段历史 | 人 / AI 修改互读；revision 与账号保护；未知 / 清空有区别 |
| P2 | 正式迁移、旧 ID、完整备份 / 同步、跨版本拦截、计划失效 | 恢复摘要一致；新机接续；旧版拒绝；未同步分支保留 |
| P3 | 简历组合、缺项审阅、文案版本，接中兴 / 京东 / 讯飞 / 蚂蚁 / 腾讯已知字段 | 不重复生成项目卡；项目 / 论文独立；差异可追溯 |
| P4 | 人工任务 / 进度、可选 AI 协作、导出与原件绑定 | 无模型也能维护完整求职记录；AI 从同一服务接续 |

P0/P1 先落实，P2 验证通过后切本人主库。公司适配逐家扩展，不作为核心改版前提。合成、本人数据迁移、网页、真实网站、安装插件分别验收。

当前已落地首轮事实模型与第二轮意向、方案、答案和决定的共用服务及网页入口。schema 4、portable v3 覆盖新实体；完整备份 / WebDAV 同时保留设置、附件和历史，旧备份可暂存升级。旧偏好只作为整理输入及历史，不能双写为另一套有效规则。本轮验收要分别核对源码、私有数据迁移、备份恢复、网页、同步、真实网站及安装插件；本文不提前宣告这些验收通过。下一轮优先补各公司的明确映射、条件必填与读回证据，将方案及公司答案接入同一 fill 服务。
